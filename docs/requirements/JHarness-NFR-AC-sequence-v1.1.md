# J-Harness NFR / AC 开发与测试推进顺序

依据：[JHarness-PRD-v1.1.md](./JHarness-PRD-v1.1.md) 第 8、10、11、13 节及关联 FR。

本文是实施顺序建议，不修改需求基线。进度更新（2026-10-15）：M0～M7 选定范围的本地开发与验收已收口；最新 Windows / Linux 容器各 260 项测试通过，均 0 失败、0 错误、0 跳过，236 个 Java/POM 哈希一致。四组真实 Docker 结果覆盖执行环境/SDK、Skills、只读 Subagent 和最终打包 CLI/Web/SDK 联合链路。M4 的两种 Maven 示例重复真实 DeepSeek 验收为历史独立证据，不表示当前构建重新进行了付费模型验收。

“阶段范围收口”不等于 PRD 全部子项已经实现。自动只读工具并行/通用重试与限流插件、图片输入、Desktop 等仍有缺口；Workflow/PTC/Goal/Schedule/LSP 等按范围决定延期。没有 Git remote，Windows/Linux/macOS 远端 CI 未执行，macOS 无实机证据，因此 PRD13 的完整发布 DoD 尚未满足。详细对照见 [2026-10-15 需求状态审计](../testing/requirements-status-2026-10-15.md)、[M7 收口](../testing/M7-closure.md) 和 [上游范围决定](upstream-capabilities.md)。旧阶段验收记录保留历史语境。

后续执行入口：[JHarness-next-plan-v1.0.md](JHarness-next-plan-v1.0.md)。默认先 M8 核心缺口，再 M9 发布验证、M10 Web前端、M11 Desktop；M12 为按需扩展候选。M9 本地准备可提前，远端执行依赖明确仓库目标。新编号是实施排期，不改变原 PRD 的 M0～M7 定义。

## 1. 推进原则

- 开发和测试在同一工作项内推进：明确 FR/NFR/AC → 准备夹具与通过标准 → 实现最小切片 → 正常、错误及负面测试 → 集成验收 → 保存证据。
- NFR 是贯穿实现的质量约束，AC 是具体验收场景，不能作为两条独立队列分别排期。
- M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7 保持需求文档的关键依赖顺序。前置接口稳定后，可提前准备后续夹具和契约测试；集成与阶段退出仍依赖前序能力通过。
- 每阶段只验收当时已具备的能力；用 Fake LLM 或替身通过的测试应标记为契约/集成证据，不能冒充真实项目端到端验收。
- AC-01～AC-15 均为 V1 发布门槛；AC-16 属于 V3。M5 负责恢复与存储能力完整化，不能承接未完成的 V1 持久性最低保障。

## 5. 编码前需要明确的基线差异

以下处理用于本计划排期；涉及契约变化时，应在需求基线中正式澄清。

1. **M5 的退出条件列出 AC-08、AC-09，但 AC-08 是文件并发变更。** AC-08 主验收放 M2；M5 只验证恢复后的版本保护。AC-09 标注「V1 起适用」，第 13 节又要求 AC-01～15 全通过，因此 M4 必须已有最小恢复检查与人工核实 UNKNOWN 的路径。
2. **AC-10 也从 V1 起适用。** V1 必须有单写者、尾部损坏处理和未来版本拒写；M5 可后置的是完整迁移工具、查询与恢复体验。基础版本规则不能延期。
3. **FR-09.4 的进程清理条款引用 AC-06，实际对应 AC-07。** 本计划按 AC-07 验收清理状态与残留报告。
4. **FR-10.1 与 FR-06.3 的事件顺序表述不一致。** M1 已通过 [实施契约](../development/M1-contracts.md) 和顺序测试固定为 FR-06.3 管线：解析/校验/作用域 → tool.requested → 策略/审批 → 意图确认 → 执行 → 结果事件。tool.requested 仅是请求事实，审批与检查点必须先于副作用执行。PRD 原文保留，后续需求版本可据此统一措辞。
5. **落盘失败时「日志可看到失败记录」需要区分存储通道。** 同一不可写介质无法保证追加 checkpoint.failed 成功。M2 应定义可用的独立诊断通道、结构化失败返回及事件录制证据，并澄清其与持久 Session 日志的区别；不能把内存事件当成已持久化记录。工具主体不得进入的断言仍必须成立。

## 6. 进度与证据记录规则

每个工作项以一个主要 AC 或 NFR 为锚点，记录关联 FR、里程碑和依赖，使用以下状态：

`待开始 → 测试/夹具已准备 → 开发中 → 自动化通过 → 集成验收通过 → 阶段完成`

失败项回到开发中；缺少实现、证据或必要环境的项不得标记通过。NFR 可以在多个里程碑反复验收，阶段通过不表示以后不再验证。

证据至少保存：需求 ID、代码版本、测试名称/命令、平台与配置、预期/实际结果、失败日志或事件引用。真实模型端到端评测另外保存任务集、项目夹具、模型及配置、重复次数与每次结果；PRD 未规定次数，本计划不自行设定发布合格率。

每个功能完成时同时核验第 13 节 DoD：相关 FR/AC、正常及错误测试、安全负面测试、权限与事件证据、明确终止状态、可重建/先落盘约束、服务与扩展点接入、文档及 CI。不得等到里程碑末尾才开始补测试。
