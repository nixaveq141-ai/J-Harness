## 判断方式与可信范围

用户明确授权多代理分模块核实。核心 500 条、API/CLI/事件/插件/策略及测试等 658 条、前端/脚本/SDK/构建等 624 条、文档/第三方等 675 条；分工内有再次交叉核实，最终以稳定 ID 合并，一条只能有一个最终裁决。

各 `notes-*.md` 是模块补充说明，其 A/B 等局部阶段命名仅为合并输入；执行顺序以总计划 R0～R6 为准。交叉核实的 delivery 80 条已合并到其 624 条主裁决文件，独立补充记录只用于一致性核对，不重复计数。

逐条依据原文定位文件，检查相邻实现、实际调用边界、阶段契约和已有测试。accepted 为建议的核心事实/修复方向成立；partial 只采纳理由明确支持的部分，可能同时拒绝原严重度、利用场景或具体改法；rejected 为错误前提、已有防护、明确范围外、纯风格/猜想或不合理修法。不能把 partial 当整条确认，也不能把“未复现”直接算误报。

这是 **全量意见的静态核实**，不宣称 2457 个故障场景都已动态复现。测试增强项说明的是现有回归的具体盲区，不等于当前产品一定有相应故障。竞态、性能、掉电/跨平台影响在计划验收中安排确定性触发与实机证据；没有这些结果前不标为已修复或新测试通过。

每条裁决保留具体理由与证据引用。原建议可能破坏契约时明确拒绝，包括：吞持久化失败后继续发请求、UNKNOWN自动重放、给未完整工具参数补 `{}` 后执行、缺平台能力改skip、删全部历史凭据/日志、把原事件body/异常明文送出、将工具摘录提升为system消息。部分来源/许可意见只核本地材料及官方原文，不给出分发违法的推定结论。

OCR-1821 的部分采纳仅为 Wrapper 许可来源映射说明；[固定版本 Wrapper LICENSE](https://raw.githubusercontent.com/apache/maven-wrapper/maven-wrapper-3.3.4/LICENSE) 已读取。java-annotations 24.0.1 是否另有 NOTICE 的子主张未取得固定 tag 完整官方树证据，读取 Cache miss 不是不存在证明，不要求凭空补文件。GNOME 参数签名误报的官方证据随 OCR-0328 裁决保存。
