## 保留的失败与限制

早期失败及过期运行保留在 `.build-cache/R2/`，新验收报告列出可用摘要，不计为最终通过。包括受限沙箱临时目录改名、带空格 JVM 参数、旧夹具孤立 context；Windows 空 fileKey 与 NTFS 创建时间隧穿促成 UUID 锚，404/空记录混淆已修复。Windows 相同 owner 重设被拒促成仅在不同身份时赋权。真实非 root Docker worker 暴露 chown 限制，现明确上报 owner/group 未保留并严格核 mode，没有新增容器能力。

早期 WebKit 严格运行时诊断失败保留；k 首次矩阵也在 turns 的停机/切换访问控制诊断处失败，业务恢复断言通过但矩阵明确失败；保留后同源码同 JAR 完整重采，turns通过，但questions在25个业务检查后仍出现display/browser-session/task访问控制诊断，严格异常断言失败。补齐其余5个WebKit夹具后通过总数为245；完整矩阵仍FAILED。该余项交R6定位，未放宽断言。questions 夹具显式 kill 自己的宿主前登记已停止 origin，客户端反例仍保证活动 origin 诊断会失败，没有放宽错误断言。曾误启动重叠 h/i 验收导致证据被并发清理，这两轮均作废；结束相关进程后，j 轮因最终差异复核发现空源产物目标保护缺口而被取代；先用旧 JAR 复现，补同一用例反例后，k 轮完整串行重采并复核。

继续会话时捆绑 Python 可执行文件已自动更新，旧补充运行时摘要被严格门禁拒绝，源码/JAR未变。重采时 Docker 引擎尚未运行，current 首轮失败；启动本机引擎并核实失败容器不存在后，另存 supplemental-k-current2 重新复核通过，旧回执保留。
