# stdio JSON-RPC 1.0

> 记录范围（2026-10-26核对）：本文保留原阶段设计、取证或验收快照；旧测试数、接口版本和“尚未/待授权”等描述按原日期解释。当前交付与后续任务见[当前状态](current-state.md)及[全阶段审计](../testing/M1-M10.5-gap-audit-2026-10-26.md)。77e8855的三平台完整验收已通过；专项余项以审计清单为准。

启动：`java -Dfile.encoding=UTF-8 -jar JAR --workspace PATH --config JSON sdk-stdio`。每行一个严格 UTF-8 JSON 对象，无日志/banner混入 stdout。请求精确包含 `jsonrpc:"2.0"`、字符串 `id`（最多64字符）、`method` 和对象 `params`；拒绝重复字段、尾随值、未知字段/方法。不支持通知、批量或任意HTTP转发。先调用 `initialize`，参数精确为 `{"protocolVersion":"1.0"}`；协商失败后不运行任务。响应相关原id，含 `result` 或 JSON-RPC `error`（稳定业务码在 message/data 中）。

| 方法 | 参数 |
|---|---|
| initialize | protocolVersion |
| shutdown | 空对象 |
| session.open | 可选 profile（默认default）、sessionId；返回 handle、真实sessionId或空字符串、DRAFT/OPEN及persisted |
| sessions.list | 可选 profile、view（默认all）、after；每页32 |
| input.send | handle、text、requestId；可选 modelId、kind（message/supplement）；首次只能message |
| request.get | requestId，核对首次受理 |
| input.get | sessionId、requestId，核对后续输入 |
| events.list | sessionId；可选 after、limit（默认32，1～100） |
| questions.list | sessionId；可选 offset |
| question.answer | sessionId、questionId、turnId、callId、requestId、selected、text、skip |
| approvals.list | sessionId |
| approval.decide | sessionId、approvalId、callId、approved、reason |
| session.cancel / session.result / session.report | sessionId |
| session.artifact | sessionId、artifactId；可选 offset、version，分页脱敏文本 |
| content.search | text、mode、profile、view、sessionId、cursor、limit、rebuild；空profile/sessionId/cursor用空字符串 |

首次输入返回 task、sessionId、kind=initial、requestId；后续返回既有轮次受理记录与 kind=continuation。重复初始 requestId 在同句柄走原幂等受理；进程重启后先 request.get 对账再打开真实sessionId。其他响应沿用同版本Web服务结构，不把句柄当持久会话ID。问题/审批须使用查询返回的精确关联字段，权限与模型连接仍由原服务检查。

服务输入64KiB，响应512KiB，内部固定loopback请求10秒边界；一次串行dispatch，系统管道提供有界传输背压。草稿句柄上限32，不可无限累积。非法UTF-8/超长/截断帧返回协议错误后退出2；其他业务错误保留进程。SDK各自待决上限32、默认15秒超时（0.1～60秒）、严格响应和相关ID；迟到回复丢弃，不重试。请求内容与秘密均不回显到协议错误。

客户端拥有且只终止其创建的Java进程。shutdown/EOF触发宿主关闭；3秒shutdown应答等待、5秒优雅进程等待后可终止自有子进程。断线/取消不是成功证明；UNKNOWN保留，不自动清除或重放。stderr被排空但不保存/回显；loopback凭据随机生成且仅存在内存。模型凭据来自环境/已有系统凭据，不进入argv。独立协议不宣称兼容Cordis或其他SDK。
