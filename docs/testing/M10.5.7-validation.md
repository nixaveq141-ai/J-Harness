## 复现与保留记录

先`npm --prefix frontend run build`、`npm --prefix frontend test`，再`mvnw.cmd -B clean verify`。设置`JHARNESS_BROWSER_CHANNEL=chrome`，逐个运行`node frontend/tests/{extensions,content,questions,models,settings,turns,history,diagnosis,browser}.mjs`；Windows启动器和凭据入口为`scripts/test-open-workbench.py`与`scripts/test-native-credentials.py`。`scripts/collect-m1057-evidence.py`要求最终计数、源码/JAR/UI/旧回归与截图一致才归档通过。

开发中失败均保留于`.dsh-tmp/m1057-*`及`.build-cache/`：初次Java局部变量重名、TS括号错误；受限环境三项HTTP无法建立loopback；新夹具误计环境工具；路径校验前移触发既有SDK Spec时序假设，最终保留原SDK时序并给CLI/预览复用显式校验；浏览器字段说明并入可访问名称，已修正标签结构。两轮中途补强后格式门禁失败，最终冻结源码后完整重验，未放宽格式或断言。浏览器错误状态首轮错误期待连接装配失败为FINISHED，实际保守规则为UNKNOWN；改为保持UNKNOWN并验证其占用，同时将确定缺失凭据前移到受理前拒绝。首次证据采集早于基础浏览器结束，因JAR不一致正确拒绝，最终全部完成后采集通过。
