- 同一taskId/sessionId追加后续轮次；每条message/supplement独立幂等受理，SDK记录输入userEventId，目录记录实际Loop turnId，所有prepared请求从日志前缀重建。恢复后的归档会话按最新archived/restored事实判断。
- FIFO最多8条待执行、每会话256条后续受理、32条分页；补充仅在当前完整轮次及SDK清理后的下一轮生效，不改变在途模型请求或已批准参数。已排队可取消，已开始仍走原取消/未知恢复约束。
- 重启将未开始项显示为PAUSED，显式开始队首；started未结算为UNKNOWN，原SDK及目录离线核实后仍不自动续跑。工作区占用跨目录/别名保持，不能通过新消息或队列取消解除。
- 受理前/开始前检查点故障不进入新SDK，指针与原目录恢复为UNKNOWN；故障注入、离线精确核实及显式新行动均有Java证据。Web目录2备份升级至3，原迁移/未来目录/65条生命周期回归保持。
- 草稿只留页面内存；待核对锁定输入/方式/丢弃，提交ID刷新后仅GET核对，不自动POST。导航和设置保护草稿；后台队列更新不抢占向上阅读位置。真实CLI/Chrome覆盖丢响应、刷新、双击、两客户端、重启/UNKNOWN和显式恢复。
