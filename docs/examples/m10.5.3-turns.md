# 多轮对话与消息队列

打开web-ui.cmd，创建任务或选择既有会话。结束后底部仍保留“继续会话”：发送后续消息会追加到同一个会话日志，模型可看到已有上下文；不会新建无关联的会话。

“下一轮消息”和“补充指令”都使用独立受理ID。忙碌时进入FIFO队列，补充指令在当前完整轮次及清理完成后的下一轮应用，不修改已发出的请求或工具审批。展开“消息队列与轮次”查看实际受理状态及Loop轮次ID；尚未开始的消息可“取消排队”，已经开始的请使用“取消任务”请求停止当前轮次。取消不是撤销已发生操作。

每会话最多8条待执行消息、256条后续受理，队列按32条分页。超限明确拒绝。未发送草稿仅本页内存保存；刷新会丢失，切换会话/设置前先发送或丢弃。密钥及草稿正文不进浏览器存储，页面只保存不含内容的提交标记。

发送后连接中断或响应丢失时，点击“核对消息受理”，只用GET读取原提交。不要盲目再次发送；刷新不会自动POST。未找到时可明确清除本页标记，该操作不会撤销可能已受理的执行。

宿主重启后，尚未开始的消息显示“已暂停 · 需显式开始”，必须由你点击队首“开始这条消息”；不会自动重放。如果前一轮为UNKNOWN，先按执行诊断完成原CLI离线核实，再决定开始或取消队列。核实不等于任务成功，也不会自动开始后续消息。归档后需先恢复会话才能继续。

重启可能使用新端口；在左侧重新选择原会话即可读取服务器队列。仅保存在旧端口页面的未发送草稿不会跨端口迁移。新Web目录格式为3，升级时先备份版本2目录；旧宿主拒绝继续写入，SDK及JSONL格式保持兼容。
